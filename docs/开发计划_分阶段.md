## 产品与服务形态（吸收自调养咨询方法论）

架构解决"判定对不对"，这一节解决"用户为什么会用、会不会照做、愿意为什么付费"。

### 1. 接受度四段法 → 产品映射

| 段 | 咨询做法 | 产品落点 | 阶段 |
|---|---|---|---|
| **命名** | 用客户能验证的体验描述问题，不甩术语 | 体质问卷结果页：不说"脾虚湿盛"，说"睡够仍不解乏、下午最沉、饭后想躺" | P2 |
| **赌注** | 只给 1~2 个动作 + 可观察指标 + 明确期限，把"信我"换成"试两周" | 方案页下方加「两周小实验」卡：1 个动作 + 3 个观察指标 + 复诊日期 | P2 |
| **可行** | 口味/场景/家庭/成本四条约束排专业度之前 | 每条推荐给「二选一」替换（粥腻了换山药排骨汤）；场景化忌口（食堂党怎么选），不是禁令清单 | P2 |
| **闭环** | 先让客户说变化，再补下一步 | 3 指标打卡（腹胀/大便/饭后困），两周后生成对比卡 | P3 |

**关键判断**：用户不接受方案，九成不是方案不专业，而是这件事在他心里"不是他的事"。所以产品的首要任务不是"讲清道理"，而是"让他自己验证一次"。

### 2. 异议分类 → 前端「常见疑问」页

把六类真实异议写成合规话术（不新增医学内容，只解释机制）：

| 用户说 | 背后顾虑 | 页面回答方向 |
|---|---|---|
| 中医不科学 | 怕被骗 | 不谈理论，谈可验证：「每条结论都能点开看规则与出处」 |
| 我太忙 | 怕失败 | 「一次只看一道菜，不用填长问卷」 |
| 以前试过没用 | 挫败 | 「这里给的是具体菜，不是泛泛建议」 |
| 太贵 | 价值不明 | 「本地规则免费，AI 解释自带 Key」 |
| 家里反对 | 缺支持 | 导出 TXT 可给家人看，含出处 |
| 能不能快点好 | 期待错位 | 明确写「不承诺疗效，不替代就医」 |

### 3. 形态层级（L1–L5）与当前位置

| 层 | 形态 | 我们 |
|---|---|---|
| L1 内容 | 科普、自测题、忌口图 | 无 |
| **L2 工具** | 单菜查询「这个菜能不能吃」 | **已在做，最高频入口** |
| **L3 方案** | 带规则依据的方案卡片、可导出文件 | **已在做** |
| L4 系统 | 记录、随访、体质档案、多人体质 | P3 起 |
| L5 接口 | 嵌进食堂点餐/外卖的宜忌标签 | 不做（超单人范围） |

**演进路径**：L2 做入口 → L3 做交付物 → L4 做留存。不做 L5，不碰"诊断/开方"。

### 4. 选型三问（每次加功能前先问）

1. 用户在哪一瞬间最需要？——点餐前 30 秒 / 饭后不适 / 体检报告出来后，三种瞬间对应三种形态。
2. 交付成本随用户数增长吗？——咨询会增长，卡片不会。先用不增长的形成入口。
3. 用户能不能自己验证？——能量化的（今天避开了哪几道、两周后腹胀减轻）才留得住。

### 5. 解释层三层（免费 AI）

| 层 | 成本 | 联网 | 说明 |
|---|---|---|---|
| 模板解释 | 0 | 否 | 默认，用规则依据拼话 |
| 共享额度 | 项目方 | 是 | 演示用，按会话限次 |
| 自带 Key | 用户 | 是 | 不满意免费额度时自选模型 |

详见 `docs/免费AI接入.md`。

### 6. 产品层底线

- 只卖「信息筛选、决策辅助、可追溯的宜忌结论、餐单组织」，卖不了「治好」。
- 不出现穴位、剂量、疗程、疗效承诺；红旗症状一律建议就医。
- 不制造焦虑促使用。
