# 从本地到商业化：现状与路径

> 2026-11-19　｜　结论：技术上"能上线"，商业上"还没验证需求"。先花 4 周验证，再谈形态。

## 一、现状：完全本地

| 层 | 现状 | 商业化差距 |
|---|---|---|
| 前端 | Streamlit 单进程 | 无账号、无多租户、无分享链接 |
| 服务 | `shafe_mvp` 模块 | 无 HTTP API，第三方接不进 |
| 数据 | 本机 SQLite（WAL） | 云端无持久化，多实例不共享 |
| AI | BYOK / 共享额度 | 额度按会话，无法跨设备 |
| 合规 | 有免责声明 | 缺隐私政策、数据来源声明、用户协议 |

**能上线**：`streamlit run` 即可，免费方案（Streamlit Community Cloud）10 分钟能出链接。
**不能直接卖**：没有账号体系、没有计费、健康类内容无合规文本。

## 二、商业化真正的三道坎

### 1. 合规（最高，且不可绕过）

| 风险 | 说明 | 对策 |
|---|---|---|
| 医疗边界 | 一旦出现"诊断/证型/疗效"，可能被认定为医疗行为 | 只说"饮食参考"；不出现证型判断；保留免责 |
| 广告法 | 食品/健康类不得宣称疗效 | 文案禁"治疗/改善/根治"；`consistency.py` 已能拦一部分 |
| 个人信息 | 体质问卷属**敏感个人信息**（PIPL） | 不落库、不关联身份；如要落库需单独同意 + 加密 |
| 数据版权 | 成分表、菜谱、食堂菜单 | 不整体复制成分表；食堂菜单属公开信息但需注明来源 |

> 结论：**卖"信息筛选与决策辅助"是安全的；卖"调理方案/疗效"是危险的。** 产品形态必须服从这条线。

### 2. 形态：卖给谁

| 路线 | 客户 | 收费点 | 难点 |
|---|---|---|---|
| **A 开源 + 数据众包** | 高校学生、开发者 | 无直接收入；靠口碑与服务 | 变现慢，但最省合规成本 |
| **B 嵌入食堂/点餐系统** | 高校后勤、餐饮公司 | 按校授权 / 按接口调用 | 销售周期长，需资质与案例 |
| **C C 端订阅** | 学生个人 | 会员 / 次数 | 获客贵、合规压力大、留存难 |

**学生的现实排序：A 打底 → B 变现 → C 不做。**
理由：A 几乎零成本，还能积累多校区数据（你的护城河就是数据）；B 的付费方是机构，不需要你投广告；C 需要投放和客服，单人扛不住。

### 3. 成本

| 项 | 量级 |
|---|---|
| 托管 | Streamlit Cloud 免费 / 阿里云 60~120 元/月 |
| LLM | BYOK 转嫁用户；共享额度 20 次/会话，约 0.01~0.03 元/次 |
| 数据库 | 免费额度足够早期；Postgres 托管约 0~50 元/月 |
| 合规文本 | 自己写 + 模板，0 元；律师审 2000~5000 元（可选） |

## 三、90 天最小商业化路径

**第 1~2 周：把 demo 挂上去**
- 部署只读公开实例（访问码 + 限流）
- 补隐私政策、数据来源声明、用户协议三页
- 埋点：访问量、方案生成次数、查询次数（不采身份）

**第 3~4 周：验证需求**
- 目标：50 个真实用户、200 次方案生成
- 看三个数：次日留存、人均查询次数、"换一道"点击率
- 如果次日留存 < 15%，说明是玩具不是工具，**停下来改产品，不要继续做架构**

**第 5~8 周：补最小商业化能力**
- 邀请制账号（邮箱 + 邀请码，不做支付）
- 数据落库（Postgres），Checkin 跨设备
- 反馈 → 候选 → 审核链路开放给外部贡献者

**第 9~12 周：谈第一个 B 端**
- 目标：一个学院/食堂的后勤，免费试点
- 交付：嵌入其点餐页的「宜忌标签」接口（3 个端点）
- 这一步才需要 FastAPI——**不是现在**

## 四、要动架构的地方（按顺序）

1. **SQLite → Postgres**：多用户写入、云端持久化。`rule_engine` 的 SQL 大部分可复用。
2. **拆 API**：`/plan`、`/dish`、`/feedback` 三个端点，`rule_engine` 不动。
3. **账号与额度**：邀请制 + 每日次数；健康数据不落库只存会话。
4. **可观测**：错误率、延迟、LLM 失败率；现在只有本地压测。
5. **部署**：Docker + 一个云主机；或 Streamlit Cloud 先跑 demo。

## 五、我的判断

**现在最该做的不是商业化，是"验证有没有人要"。**

你已经有的东西（320 条数据、133 条金标、19 条审核规则、可追溯判定、0 违规压测）在答辩里很值钱，但在商业上只证明"做得认真"，不证明"有人付钱"。

用 4 周、零成本拿到 50 个真实用户的数据，比直接写 3 个月 SaaS 代码更有价值。如果数据好看，B 端授权是水到渠成；如果不好看，及时止损。
