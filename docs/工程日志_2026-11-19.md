## 三、关键决策

### 3.1 为什么选开源

三条路里，开源的合规成本最低、数据能滚起来，且"被使用"比"被付费"更容易先拿到。
代价是短期没有收入——这对学生项目不是问题，对创业公司是。

### 3.2 不直接公开现有仓库

历史提交里有照片和姓名，`git log` 一样能看到。所以发布的是**单提交的干净仓库**，
由 `scripts/export_public.py` 从当前跟踪文件重新生成。

### 3.3 数据不入库

`food.db` 从版本库移除，改由 `init_db.py` 生成，应用启动时缺失则自动初始化。
好处是没有隐私与体积问题；代价是云上实例每次冷启动要重建（约 3 秒）。

## 八、复盘

**做对了**：发布前做"全新克隆验证"。如果直接推上去，CI 会红，第一个外部用户会失败——而且我大概率会以为是环境问题。

**做得不好**：导出脚本第一版只复制文件、不管 git 状态，导致你在半个仓库上折腾了 20 分钟。工具要么做完整，要么别做。

**最值钱的一条**：`src refspec main does not match any` 不是网络错误，是"本地没有提交"。这类报错的含义比它的字面更远，值得写进技能。
