# 知源智膳 · 任务推进

先加载 `zhishan-playbook`（规则与门禁）。数据任务再加载 `zhishan-data-intake`。本技能只管**推进节奏与取舍**。

## 0. 铁律

1. **一次只推一个最小可验收单元**。做完 → 验证 → 提交，再谈下一个。不要一个回合改五处。
2. **没有验收命令的任务不算完成**。`python tools.py gate` 是底线。
3. **遇到需要人拍板的，停下来问**，不要替用户决定（见第 4 节）。
4. **不编造**：没数据就说没数据，不拿占位符冒充结果。

## 2. 下一个任务怎么选（按优先级，不按兴趣）

```
① 有没有"红"？
   gate 失败 / 指标回退 / 数据断裂 → 先修，别的都往后排

② 有没有"卡在别人身上"的？
   导师裁决、同学试用、需要外采数据 → 先催，催不动就做能做的

③ 计划内的 P4 交付物
   试用报告 > 白皮书 > 答辩 PPT > 演示视频 > 公开实例

④ 锦上添花
   体验优化、新功能、重构 —— 只有 ①②③ 都清空才做
```

**默认否决**：不在计划里的新功能。想加先写进计划，再排期。

## 3. 单个任务的闭环（五步，缺一不可）

```powershell
# ① 读现状（别凭记忆）
python tools.py gate
git status --short

# ② 改（一次只碰一类文件：数据 / 引擎 / 前端 / 文档）

# ③ 验证（必须能跑）
python init_db.py          # 改了数据才需要
python -m unittest discover -s tests
python tools.py gate

# ④ 写文档（改了行为就要写）
#    docs/ 下补记录；docs/开发计划_分阶段.md 勾选；架构数字变了改 docs/系统架构.md

# ⑤ 提交（信息写清：来源、改了什么、指标变化）
git add -A
git -c user.name='huangdengyu' -c user.email='629660171@qq.com' \
    commit -m "feat(P4): ..." --no-verify   # 沙箱内 hook 跑不了 sh；本机去掉 --no-verify
```

**验收标准**（全绿才算完）：

| 检查 | 期望 |
|---|---|
| `tools.py gate` | 单元测试 / 六项指标 / 数据完整性 / 文案一致性 / 无档口 全 PASS |
| 指标 | 准确率只升不降；违规率 0 |
| 文档 | 行为变更在 docs/ 有记录，计划勾了 |

## 4. 必须停下来问用户的六种情况

| 情况 | 为什么要问 |
|---|---|
| 医学口径（发物档位、温补是否禁） | 规则变更，需导师裁决，不能自己定 |
| 产品取舍（素食口径、要不要某功能） | 影响用户体验与范围 |
| 外部数据（食堂菜价、档口、真实试用反馈） | 编造即失真 |
| 要动 `rules.csv` 的医学条文 | 已审核规则，改动需重新走审核 |
| 指标无法达标且需降低目标 | 目标由立项书定，不能私自下调 |
| 发现安全/隐私问题 | 影响部署与合规 |

问的时候给**选项 + 我的建议 + 影响面**，不要只抛问题。

## 5. 推进时的默认动作

- **每个回合结束时**：说明"做完了什么 / 验证结果 / 下一个建议"，让用户一句话就能决策。
- **发现新问题时**：先记进 `docs/` 或计划，不要顺手扩大范围修掉。
- **数字要现算**：规模、指标、通过率，跑命令取，不引用旧记忆。
- **提交粒度**：一个可验收单元一个 commit；文档与代码分开提交更清晰。
