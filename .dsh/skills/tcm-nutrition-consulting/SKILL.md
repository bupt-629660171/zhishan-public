# 中医调养咨询 · 接受度与交付形态

一句话立场：**客户不接受调养方案，多数时候不是方案不专业，而是这件事还没变成"他自己的事"。** 所以工作不是说服，而是设计三个条件：他认同问题、他不会失败、他自己看得见变化。

判定权、数据与规则改动不归本守则管 —— 涉及 `rules.csv` / `tags.py` / `food.csv` / AI 判定边界时，先加载 `zhishan-playbook`，冲突以它为准。

## 0. 什么时候用 / 不用

| 用 | 不用 |
|---|---|
| 写方案、写解释、写随访话术 | 改规则、标签、菜品数据（→ `zhishan-playbook`） |
| 处理异议、诊断"客户为什么不执行" | 下诊断、开药、判断是否该停药 |
| 产品形态选型与文案落地 | 承诺疗效、替代就医 |

## 1. 硬边界（先于任何话术）

1. **不诊断、不承诺疗效、不替代就医。** 遇到红旗症状 —— 不明原因消瘦、便血/黑便、持续或夜间痛、发热不退、进行性吞咽困难、可触及肿块、孕产与婴幼儿特殊情况 —— 停止调养建议，明确建议就医，并说明"这不在我的范围"。短期丢单换长期口碑，这笔账永远划算。
2. **不制造焦虑成交。** "再不来就晚了""你这体质早晚出问题"一律不用。
3. **产品出口违禁词**（与 `shafe_mvp.validate_ai_text` 的 `AI_FORBIDDEN_TERMS` 一致）：穴位、按揉、针刺、艾灸、针灸、推拿、刮痧、剂量、毫克、克数、处方、服药、用药、疗程、根治、治愈、包治、疗效保证、替代就医。面向知源智膳生成的任何用户可见文本，出现即触发降级，不得放行。
4. **结论为「禁」时**，文本中不得出现"可以吃 / 能吃 / 放心吃 / 建议食用 / 推荐食用 / 不妨吃"。
5. **解释可以改语气，不能改结论。** 大模型只解释已放行的结果，不参与"能不能吃"的判定。

真人咨询中可谈饮食结构、起居节律、情志与运动；涉及穴位、艾灸、方药的内容默认不写，即便客户主动追问，也只说"这部分需要找执业医师"，并且**永远不写进产品文本**。

## 2. 接受度四段法（A→B→C→D）

目的是让客户自己得出结论，而不是让他相信你。

### A 命名：把术语翻成他能验证的体验

结构一句话完成：**复述体验 → 给出区分 → 落到判断 → 留校准口**。

> 「你说的这个累，我猜是睡够了也不解乏、下午最沉、吃完饭想躺的那种，而不是熬夜那种困。对得上吗？」

- 判据：客户说"对，就是这样"——信任一半已经成立，因为他被看懂了。
- 失败信号：你在讲理论、他在看手机 → 立刻停讲，改提问。
- 反例：「你脾虚、湿气重、气血不足」三连诊断。他无法验证，只能选择信或不信，而默认选项是不信。

### B 赌注：两周内可验证的单一动作

一次只给 **1–2 个动作 + 1 个可感知指标 + 明确期限**。

> 「这两周不要求你做到全部，我只想验证一件事：你的身体对这个方向有没有反应。有反应我们往下走；没反应，说明我判断错了，方案要改。」

| 要素 | 写法 |
|---|---|
| 动作 | 早餐把冰牛奶换成小米山药粥；晚饭七分饱 |
| 指标 | 舌苔厚薄、大便是否成形、饭后困倦、晨起口苦、入睡时间 |
| 期限 | 首次 2 周 → 4 周 → 8 周 |

关键把"信我"换成"我们一起做个实验"，并把"可能无效"的责任先揽到自己身上。
失败信号：客户问"是不是要吃很久" → 期限和验证点没讲清，回到 B。

### C 可行：把依从性当第一约束

按顺序过四个现实约束，任何一条过不去，方案就要改简单：

1. **口味** —— 每个推荐配一个"他吃得下的版本"（代茶饮太苦 → 陈皮山楂加两片甘草）。
2. **场景** —— 外食/食堂/出差写成"这个场景里怎么选"，不是"不许吃"。**硬忌口 ≤ 3 条**，其余写"少一点"。
3. **家庭** —— 中餐共餐，方案要能被家人一起吃；主动问"家里谁做饭、愿不愿意配合"，别让客户单独开小灶。
4. **成本与时间** —— 说清食材、煎煮、费用的门槛，并给平价替代。

然后**给二选一，不给命令**：「早上要么粥、要么山药糊，你挑一个做得下去的。」
失败信号：客户说"我尽量" → 方案仍然太重，继续砍，直到砍到"不构成负担"。

### D 闭环：让他自己说出变化

复诊**先让他说**：

> 「这两周你自己感觉有什么不一样？哪怕很小的地方。」

他说出任何变化（哪怕只是"好像没那么胀了"）→ 把变化归因到调的方向 → 只加一点点。这是自我说服：人最信自己得出的结论。

配套：只记 3 个指标（1 分钟能写完）、固定复诊节奏、见效后主动撤掉一部分干预（让客户感到被尊重而非被绑定）、教他用自己的话复述给家人听（能讲出来才算真接受）。
失败信号：复诊全程你在说 → 接受度不会转化成复购。

## 3. 异议分类：按真实顾虑回应，不背话术

| 客户说 | 真实顾虑 | 回应方向 | 不要做 |
|---|---|---|---|
| 「中医不科学吧」 | 怕被骗、怕没效果 | 不争学理，争可验证：两周三个指标，你自己判断 | 讲阴阳五行，或贬低现代医学 |
| 「我太忙了，做不到」 | 怕失败、怕被评判 | 把方案砍一半，先造一次成功体验 | 强调"重视健康就有时间" |
| 「以前试过，没用」 | 过去的挫败 | 追问：当时具体怎么做、坚持多久、断在哪 —— 通常断在可行性 | 归因为"你没坚持" |
| 「太贵了」 | 价值不确定 | 拆账到每天，并对比他为"累"付出的代价（咖啡、外卖、请假） | 打折促销式降价 |
| 「家里人说我瞎折腾」 | 社会支持缺失 | 给家属一句能转述的说明，或邀请家属参与一次沟通 | 让客户"别管他们" |
| 「能不能快点好」 | 期待错位 | 给阶段时间表，同时**明确说清保证不了的部分** | 缩短周期迎合、许诺"断根" |

敢说"这个我保证不了"的人才会被认为可信。期望管理不是泼冷水，是提前拆掉失望。

## 4. 产品形态

两层，别混着谈：**人交付卖"有人管我"（客单价高、天花板低）；数字形态卖"我自己能判断"（获客便宜、要场景）。** 能跑通的是"数字做入口，服务做深度"。

### 4.1 人交付形态

| 形式 | 具体内容 | 变现逻辑 | 主要局限 |
|---|---|---|---|
| 体质辨识与咨询 | 60–90 分钟一对一，输出体质结论 | 单次收费 / 引流 | 不可复制，依赖个人 |
| 书面调养方案 | 2–4 周阶段方案：饮食结构、起居、情志、复诊节点 | 咨询费主体 | 客户买了不执行 |
| 周期陪跑 | 每周复诊，按反馈调整方案 | 按月/季订阅，复购主力 | 时间成本高，有产能上限 |
| 餐单定制 | 每日/每周菜单、外食点餐指南 | 低价批量 | 易被认为"网上都有" |
| 代茶饮 / 药膳包 | 按方配好的实体包 | 商品差价 | 涉及资质，风险最高 |
| 课程 / 训练营 | 21 天调养营：直播 + 打卡 + 社群 | 一对多，可放大 | 完课率低，效果归因难 |
| 机构套餐 | 体检中心、健身房、月子中心、企业福利 | B 端渠道 | 定制成本高，决策链长 |

**服务形态的真产品是"方案 + 复诊节奏"，不是那份文档。** 文档活不过一周，节点才是留存机制。

### 4.2 数字形态层级

| 层 | 形态 | 作用 |
|---|---|---|
| L1 内容 | 科普、体质自测题、忌口清单图 | 获客，不直接变现 |
| L2 工具 | 单菜查询、餐单生成、禁忌提醒 | 高频、低决策成本，最合适的入口 |
| L3 方案 | 带规则依据的每日/每周卡片、可导出的方案文件 | 付费交付物 |
| L4 系统 | 记录、随访、家庭版 / 食堂版 / 机构版看板 | 留存与扩客单 |
| L5 接口 | 嵌入点餐、外卖、体检报告解读 | B 端授权 / 按量计费 |

### 4.3 选型三问（顺序不能换）

1. **客户在哪个瞬间最需要它？** 点餐前 30 秒、饭后不舒服、体检报告出来那天 —— 三个瞬间对应三种形态。
2. **交付成本随客户数增长吗？** 咨询会涨，卡片不会。先用不增长的形成漏斗，再用会增长的形成收入。
3. **客户能自己验证效果吗？** 可量化的才留得住人。

### 4.4 知源智膳的现状与可延展形态

现状：L2 工具 + L3 方案卡片 + TXT 导出，载体是 Streamlit 单页，场景是"沙河食堂今天吃什么"，每条结论带 `rule_id` / `source_ref` / 版本 —— **可审计就是差异化**，形态选得对的是这三点：决策成本低、场景高频、结论可追溯。

| 现在 | 可长成 |
|---|---|
| 单次方案卡片 | 每日餐单 + 同档口替换建议 |
| TXT 导出 | 带免责声明与规则版本的 PDF 正式交付物 |
| 体质问卷 | 体质档案 + 周维度趋势 |
| 单菜查询 | 微信 H5 / 小程序"点餐前查一下"，最高频入口 |
| 规则引擎 | 嵌入食堂点餐系统的宜忌标签（B 端） |
| 方案生成 | 复诊提醒 + 3 指标依从记录 |

**形态与合规绑定**：卖的是信息筛选、决策辅助、可追溯结论、餐单组织；卖不了"治好"。因此"单菜查询"比"一对一辨证方案"更安全也更好复制，绝不能把产品做成"诊断 + 开方"的形态 —— 那会一步跨出 `zhishan-playbook` 的红线。

## 5. 交付前自检（五问，缺一不可）

1. 有没有**一句**客户能自己观察的指标？
2. 有没有**一个**他两周内不会失败的动作？
3. 硬忌口是否 ≤ 3 条，其余是否写成了"少一点"？
4. 面向产品的文本过没过违禁词与「禁」冲突校验？
5. 复诊时有没有留给他先说的位置？

## 6. 反模式

- 一次给全套方案换一次点头（接受 ≠ 执行，执行过的方案才算被接受）。
- 用术语建立权威（无法验证的权威只会触发防备）。
- 用恐吓成交（能收一次费，毁掉复购与转介绍）。
- 承诺"根治 / 断根 / 保证好"。
- 方案里塞客户无法观察、无法验证的环节。
- 把"见效后加码"当专业（正确动作是减负）。
- 让大模型参与判定，或让它生成穴位、剂量、疗程、疗效类内容 —— 加了"仅供参考"也不行。
