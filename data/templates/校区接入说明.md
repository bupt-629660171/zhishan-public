# 多校区数据接入说明

目标：任何人拿到模板，能在半小时内把本校食堂数据接进来，且不污染已有数据、不丢溯源。

## 一、模板在哪

`data/templates/校区导入模板.csv` —— 10 行示例，覆盖素菜/荤菜/汤/主食/油炸五类。

必须字段（缺一列直接拒收）：

| 列 | 说明 | 例 |
|---|---|---|
| `name` | 菜名，全文唯一 | 清炒油麦菜 |
| `property` | 性味，2~6 字，决定判定 | 清淡凉润 |
| `explanation` | 一句依据，写清对哪类体质怎样 | 油麦菜清热利水，少喝清炒，湿热者宜 |
| `location` | 食堂/楼层 | 示例校区一食堂 |
| `window_name` | 窗口名 | 素菜窗口 |
| `price` | 价格，未知**留空**，不要填 0 | 8 |
| `campus` | **校区，必填** | 示例校区 |
| `source_type` | 来源类型 | 档口菜单 / 档口LED菜单 / 权威文献整理 |
| `source_ref` | 凭证路径或照片名 | 示例校区一食堂菜单照片.jpg |
| `collected_by` | 采集人 | 张三 |
| `collected_at` | 采集时间 | 2026-11 |
| `kind` | `dish` 或 `ingredient`，默认 dish | dish |

可选：`calories`（千卡/100g）、`note`。

## 二、四步接入

```powershell
# 1. 先校验，不写库（dry-run）
python tools.py import 我的校区.csv

# 2. 确认"可接收"数量与拒收原因无误后，真正合并
python tools.py import 我的校区.csv --write

# 3. 重建库（导入 → 建表 → 规则 → 标签 → 忌口派生）
python init_db.py

# 4. 验收
python tools.py gate
python tools.py quality        # 看 campus 分布、来源覆盖
```

## 三、拒收规则（避免脏数据）

| 情况 | 结果 |
|---|---|
| 缺 `name` / `property` / `explanation` / `campus` | 拒收 |
| `price` 非数字或为负 | 拒收 |
| 菜名是"一大荤一素""套餐"这类档口分类 | 拒收（但"麻辣烫13元套餐"这类真实菜名保留） |
| 同名菜已存在 | 不覆盖，只补档口记录 |

## 四、多校区注意

1. **校区必须填**。`import_data.py` 现在会直接报错，不填不会被默认成"沙河"。
2. **档口价格会变**，重导入时按 `(菜品, 档口)` 去重更新价格，不会产生重复行。
3. **同一道菜在不同校区**：菜名相同则合并为一条菜品，档口记录分开——这正是多校区想要的。
4. **不要把别的校区的 `campus` 复制粘贴忘了改**，这是最常见的错误。

## 五、演示数据

模板里的"示例校区"仅用于验证格式，**不要 `--write` 进正式库**。
需要演示多校区效果时，复制一份改个校区名，导进临时库验证即可。
